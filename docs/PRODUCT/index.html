.btk/docs/ClinicQ · clinic discovery & queue

Find a clinic. Get a number. Watch it count down.

ClinicQ lets a patient geo-locate a nearby public or private clinic, join its digital queue from a phone (app, USSD, WhatsApp) or the web before even leaving home, and see a ticket number count down on the clinic's own waiting-room screen, while staff run the whole line from one dashboard. Global retail queue systems have done this for a decade; most local clinics don't have it yet.

Discovery geo-location, public/private toggle Channels PWA · USSD · WhatsApp · Web Display number/time always, name/comment opt-in Start R1,800–15,000 pilot clinic Stack Python 3.14 · FastAPI · htmx · Postgres/PostGIS Payment filter Phase 2, private clinics only

Critical: the waiting-room display defaults to number-only: name and the optional visit comment ("headache", "follow-up") are clinic-configurable and off by default, because a name next to a health-related comment on a public screen is personal health information under POPIA even though the intent is just a friendlier board.

Overview

ClinicQ is the discovery + queue + dashboard playbook for clinics, formerly sketched as ClinicQ.

Product

Find a clinic by geo-location -> join its digital queue from any of four channels -> get a ticket number that counts down on the clinic's own display board -> staff run the line from one dashboard.

Booking & digital queue

One shared queue per clinic/room/service, joinable remotely or in person, fair by arrival order, not by channel.

sequenceDiagram participant P as Patient any channel participant API as ClinicQ API participant Q as Queue participant D as Display monitor P->>API: Join queue at Clinic X API->>Q: Append ticket next sequence number Q-->>API: Ticket number position estimated wait API-->>P: Confirmation plus live position API-->>D: Queue length updates

Multi-room queues

flowchart LR IN[Patient arrives or joins remotely] --> Q1[Queue Triage Vitals] Q1 -->|Nurse calls next| Q2[Queue Doctor Room] Q2 -->|Doctor calls next| Q3[Queue Pharmacy window] Q3 --> DONE[Visit complete]
One queue, not two. Remote joins and walk-ins share one fair sequence; staff can manually reorder for genuine clinical priority, logged and auditable.

A name next to a symptom comment on a public screen is personal health information under POPIA once attached to an identity: never pair a comment with a full name by default; number-only is the safe default, same caution ElimuKadi applies to biometric consent.

System & network topology

Cloud-hosted API from day one: no local edge hardware needed, unlike card-reader or radio-based projects.

flowchart LR DASH[Reception dashboard] -->|Wi-Fi LAN| NET[Clinic internet] DISP[Display monitor Pi kiosk] -->|Wi-Fi LAN| NET NET -->|HTTPS| API[ClinicQ API cloud VPS] API --> DB[(PostgreSQL PostGIS)] PATIENT((Patient phone)) -->|Internet| API

Pros

Near-zero clinic hardware; cloud-hosted from day one; one engine behind four channels.

Cons

Depends on internet reachability for remote-join/notifications; gateway costs scale with volume.
