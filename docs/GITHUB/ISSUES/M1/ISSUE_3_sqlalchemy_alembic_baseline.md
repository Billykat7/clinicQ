# Issue 3: Async SQLAlchemy 2.x + Alembic baseline (PostGIS extension enabled)

**Area:** Backend / Database
**Milestone:** M1 - Foundation & Local CI
**Owner role:** Backend Lead
**Depends on:** Issue 2
**Estimate:** 2 days
**Status:** Planned

## Context

Every model in the project hangs off this issue. It establishes the async SQLAlchemy 2.x engine and
session dependency, the declarative base with shared mixins, and the Alembic baseline that enables the
PostGIS extension; enabling it later in the migration chain would break a fresh database rebuild.

## Scope

- Async engine and `async_sessionmaker`, plus a `get_session()` FastAPI dependency with correct teardown
- `Base` declarative class with `id`, `created_at`, `updated_at` and soft-delete mixins
- Alembic configured for async, with a baseline revision that runs `CREATE EXTENSION IF NOT EXISTS postgis`
- Naming conventions for constraints and indexes so autogenerated migrations are stable and reviewable
- A test fixture that creates and tears down a schema per test session

## Acceptance criteria

- [ ] `alembic upgrade head` on an empty database succeeds and installs PostGIS
- [ ] `alembic downgrade base` then `upgrade head` round-trips without error
- [ ] Autogenerate produces a clean (empty) diff immediately after an upgrade
- [ ] The session dependency rolls back on an exception and never leaks a connection
- [ ] Tests run against a real PostGIS database, not SQLite
- [ ] Constraint names follow the documented convention in every generated migration

## Files touched

- `app/database/base.py`
- `app/database/session.py`
- `migrations/env.py`
- `migrations/versions/0001_baseline.py`
